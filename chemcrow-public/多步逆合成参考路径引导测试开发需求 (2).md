# 多步逆合成工具协同测试开发需求

请在 /root/autodl-tmp/my_model 的现有本地项目中，实现一个可批量运行的“参考路径引导逐步测试”脚本。测试数据默认目录为 /root/autodl-tmp/my_model/dataset/PaRoutes。

## 1 测试目标与执行范围

现有项目由 Agent 调用本地单步逆合成模型、本地反应数据库和评价工具，并结合蒙特卡洛树搜索及 AND-OR 树开展多步规划。本阶段采用确定性的 Python 控制器直接调用这些本地工具，模拟 Agent 的工具调度，完成测试流程。正式测试保留真实模型推理和数据库查询，不调用远程大语言模型 API。

每条测试路线同时提供目标产物和该路线的起始底物。完整参考路线只交给测试控制器，用于候选生成后的匹配、统计和引导扩展。以 A←B*←C*←D 为例，A 是目标产物，D 是起始底物，B*、C* 是参考中间体，路线共 3 个单步反应。

每一步先获取数据库候选和模型候选，保留剪枝前的完整候选，再融合、评分并冻结排名。若任一来源实际返回了正确的完整前体组合，则选择合并池中对应的真实候选继续扩展。即使该候选位于第 4 名、第 10 名，或超出普通搜索的保留宽度，也必须继续。

若两个来源都没有返回正确前体组合，立即终止整条参考路线，返回“已命中的反应步数／参考总反应步数”。第一次失败后的步骤不再查询数据库、不再调用模型；分支路线也执行整条路线停止的规则。

主指标包括路线覆盖比例、完整引导完成率，以及合并排序的 Top-1、Top-2、Top-3 累计准确率。正确候选排第 2 名时，计入 Top-2 和 Top-3，不计入 Top-1。

### 本阶段的结果含义

本测试评价给定起始底物条件下，本地数据库与模型协同工具链对参考步骤的覆盖能力及候选排序能力。结果应标为“参考路径引导测试”，不能标为大语言模型 Agent 自主决策表现，也不能直接等同于普通 MCTS 自主搜索成功率或完整路线排名的 Top-k 指标。

本次开发包括数据适配器、逐步控制器、统计与结果输出，以及必要的最小接口修改。使用已有本地代码、权重、数据库和评分逻辑；无需重新训练模型，也无需重新人工制作测试集。

每组中，参考树根的 SMILES 与 targets.txt 同一位置的字符串逐条一致，目标字符串在组内均不重复。每组 stock 文件的字符串集合恰好等于该组全部参考路线叶节点的字符串并集。因此，stock 是整组公共库存，不能直接称为某一条路线专属的起始底物。

n1、n5 有 2,146 个相同的目标 SMILES 字符串；其中 2,128 对路线按分子字符串及有序树连接比较完全一致。因此两组分别运行、分别汇总。可以另给合计，但需注明按 20,000 条路线记录合并，不能称为 20,000 个互不重复目标，也不能静默删除跨组重复记录。

n1、n5 是数据组标识，不是反应步数。实际步骤数须遍历反应节点计算；不能依据文件名、树层数或最长分支长度推断。

### 数据校验的边界

本次已核对文件、节点结构、字段、数量及原始字符串关系；化学结构可解析性及规范化后的等价关系仍须由本地脚本使用项目分子工具校验。将上述数量作为本附件版本的校验基准，不在程序中硬编码样本数或对其他合法子集强制要求相同数量。

## 3 实际路线结构与参考步骤提取

### 分子节点与反应节点

本附件的分子节点包含 type="mol"、smiles、in_stock；非叶分子还有 children，且每个非叶分子的 children 只有一个反应节点。反应节点包含 type="reaction"、smiles、metadata、children；其 children 是该反应的全部直接前体分子。

全部 70,268 个反应节点的顶层 smiles 都是空字符串。这不是缺失参考反应，也不能据此判定路线无效。当前步骤的 product 必须取反应节点的父分子 smiles，precursors 必须取该反应节点全部直接子分子的 smiles。

反应 metadata 均含 smiles、rsmi、reaction_hash、ID、RingBreaker。metadata.smiles 是反应表示，不是单个分子；metadata.rsmi 还含试剂等信息。默认以路线树的直接子分子定义待比较前体，不把 rsmi 中间段的试剂、溶剂或催化剂自动加进前体答案。

保留 metadata 用于追溯和离线数据核验。若 metadata 与树结构存在冲突，记录具体节点并按校验策略处理，不能静默切换答案来源。任何 metadata 参考反应、专利编号或反应哈希都不能作为数据库检索条件或模型预测提示。

### 内部标准记录

数据适配器应自动生成 dataset_split、source_file、source_route_index、route_id、target、starting_materials、reference_steps。原文件没有 route_id 或 reference_steps 字段，不应要求用户补做这些字段。

source_route_index 使用从 0 开始的数组下标。建议 route_id 使用 n1-000001、n5-000001 等从 1 开始的可读编号。步骤及分子节点使用相对于路线根的 JSON 路径或等效稳定编号；输出两种编号的规则，避免索引混淆。

每个参考步骤至少保存 step_id、product_node_id、product、precursor_node_ids、precursors、后续反应连接及 source_metadata。n5 中反应 metadata.ID 有跨路线重复，不能将它单独作为全局步骤主键，也不能跨路线复用命中计数。

### 提取目标与底物

target 为根分子的 smiles；starting_materials 为当前路线的全部分子叶节点。默认底物策略为 route_leaves，将这些底物作为 building_blocks 传给模型及相关评价逻辑。分子库存接口可接收去重后的结构列表，但参考树、叶节点列表和反应前体重复次数必须保留。

本附件中叶节点均标为 in_stock=true，非叶节点均为 false；程序仍应按是否有后续参考反应识别叶节点。stock 文件用于库存核验。可选的 split_stock 对照模式须单独记录和报告，不替代默认路线底物模式。

每个参考反应都要检查完整前体组合，后续遍历只扩展仍有参考反应的前体。不能把全部后代分子作为当前前体，也不能只沿主前体或最大分子生成参考链。

以下路径相对于 /root/autodl-tmp/my_model。请在实际本地版本中核对对应入口、参数、候选截取和评分行为，再进行适配。

现有 fuse_candidates 主要按主前体与酶编号兼容性融合，可能保留数据库结构而消费模型候选。测试模式必须按第 5 节保护完整前体组合，避免其他前体不同的候选在融合中丢失。

## 5 双来源候选生成与合并排序

### 先生成并保存候选

对于当前产物 P，工具链仅可使用 P、当前路线的 building_blocks 和预设配置。固定执行数据库查询和本地模型预测；每个被尝试步骤两个来源都要调用，不能因为某个来源先命中参考答案就跳过另一个来源。

分别设置 n_model 和 n_db。n_model 是模型返回候选预算，n_db 是数据库检索上限；合并池来自二者并集。它们与原搜索保留宽度 candidate_beam_width、最终路线数 top_k_routes、统计指标 Top-1 至 Top-3 是不同概念，必须使用不同配置字段。

single_fn 的真实解码宽度可能并未接收客户端 top_k。增大客户端切片值不保证生成更多候选；应检查能否透传，记录实际限制，不补造候选。候选预算必须运行前固定，不能看过参考答案后再增加预算或重复生成直到命中。

保存原始返回顺序、原始内容和各阶段数量：requested、raw_returned、valid_returned、merged_count、ranked_count。若包装层会丢弃解析失败候选，应在其丢弃前取得原始快照，并保存无效原因。真实返回不足请求数量或正常返回空列表均保留实际数量。

### 保持完整组合的融合

为候选建立“当前产物＋规范化完整前体多重集合”的匹配签名。多重集合忽略前体顺序，但保留重复次数。主前体相同而其他前体不同的反应必须分别保留；原融合中按 noncurrency_precursors 去重的逻辑，也不能丢掉本次要求比较的完整组合。

两个来源的完整签名一致时可合并证据，标为 BOTH，保存各来源原始候选编号、数据库反应编号、模型分数及融合映射。沿用酶信息兼容条件时，冲突版本可分别保留，但不得把另一来源的不同完整组合消费掉。

必须满足以下不变量：任一来源实际返回的可比较完整组合，在合并池中仍有对应候选。数据库命中和模型命中分别从各自来源快照计算，不能仅凭融合对象的 source 标签推断。

### 排名冻结后再比较答案

复用原评价方法对全部有效合并候选评分、排序，保存 hybrid_rank，从 1 开始。相同参考组合存在多个候选时取最小排名；同时保留 model_raw_rank 等来源排名供诊断。准确率默认指 hybrid_rank，不混用两种排名。

无效分子候选保留原始记录及拒绝原因，不算命中；不通过普通搜索质量阈值的结构有效候选仍须保留、评分，标记 would_be_filtered。结构有效候选若无法完成评分，应报告 score_error，不能静默删除后继续主统计。候选与排名冻结后，测试控制器才能使用参考答案匹配。

## 6 参考路径引导的逐步执行流程

1. 解析并校验当前参考路线，得到目标、路线底物、全部反应节点和连接关系。总步数 L 按反应节点数计算，初始化 found_steps=0、attempted_steps=0。

2. 采用从目标向底物的深度优先顺序，先访问当前反应，再按其 children 原始数组顺序递归访问各前体的后续反应。以节点身份定位步骤，不按 SMILES 去重或重排分支。

3. 对当前产物按第 5 节获取双来源完整候选，保留来源快照，融合、评分并冻结排名。若任一来源异常、超时或评分失败，按第 9 节记录运行错误，不能伪装为普通未命中。

4. 在两来源快照及合并池中分别匹配本步参考完整前体组合。一次正常完成双来源获取及排名的步骤，attempted_steps 加 1。记录 database_hit、model_hit、hybrid_hit、hybrid_rank 和 Top-1 至 Top-3 标记。

5. 命中时 found_steps 加 1，选择合并池中真实存在、排名最靠前的匹配候选。按规范化结构及出现次数，将候选前体映射到对应参考子节点；下一步扩展实际候选的对应前体。重复分子用稳定的出现顺序映射，不能将不同树位置的节点合并。

6. hybrid_rank 大于 3 或大于普通搜索保留宽度时，仍继续参考引导扩展。不能把正确候选提升到第 1 名后再统计，也不能向候选池追加未被工具生成的参考前体。

7. 两来源均未命中时，将本步标为 miss，立即终止整条路线。保存 found_steps/total_steps；所有尚未访问的参考步骤标为 not_evaluated，候选及排名字段为 null。后续步骤不得继续调用工具。

8. 全部参考反应命中，且终止叶节点与指定路线底物一致时，标为 complete。保存本路线结果后继续下一条；一次步骤命中只能计数一次，不因两个来源同时命中而加 2。

### AND-OR 树与 MCTS 的关系

同一产物的不同候选反应是 OR 选择；选中反应后，所有仍需合成的前体形成 AND 分支。每个必要分支都要检查，任一分支首次 miss 即停止整条路线。这里的“连续命中步数”指固定遍历顺序下失败前的命中数。

本模式复用反应对象、评分和可复用的 AND-OR 状态推进逻辑，以参考命中选择覆盖自由分支选择，无需再为选路执行自由 UCB、随机 rollout 或非参考分支扩展。

关闭会跳过参考步骤的数据库前向锚定、自动补全及提前闭合。即使 _build_forward_anchors、_close_solved_leaves 或库存能够直接闭合剩余路线，也必须逐个参考反应生成候选并检查。是否继续由参考节点是否还有后续反应决定，不能仅按库存判断。

每个树位置的反应节点单独计数；相同分子、相同反应编号或跨路线缓存命中，都不能减少参考步数。

## 7 分子与完整反应的匹配规则

### 完整前体多重集合

以参考反应节点的全部直接前体分子为答案。A←{B*,E*} 必须完整命中 B* 与 E*；缺少一个、额外增加一个，或只有主前体相同，均不算正确。前体排列顺序不影响匹配，重复项不能删除。

本附件确实存在同一步中重复前体的情况：n1 第 237 条路线的一个反应含“有机前体、O、O”；n5 第 361 条路线的根反应也含两个 O。因此默认规则中 {R,O,O} 与 {R,O} 不相等，也不能因为 O 被工具归入 currency 就忽略它。

模型使用完整 all_reactants，数据库使用完整 precursors。若数据库以明确的整数系数折叠表示重复底物，应在适配器中显式还原用于比较的重复次数并记录规则；系数含义无法确定时标记不可比较原因，不能猜为一次。

### 统一的结构标准化

预测和参考采用相同的分子解析与规范化流程。清除仅用于标识的原子映射编号，再生成规范 SMILES；默认保留立体化学、电荷和同位素。不能只比较原始字符串，也不能用分子式相同或指纹相似度高代替结构相同。

对于模型以点连接表示完整反应物的字段，按接口约定解析成分子列表；列表中每个分子的出现次数要保留。不要根据分子大小丢掉小分子，也不要把用于库存查重的 set 直接用于反应前体匹配。

默认不增加去盐、中和、互变异构体合并或通用代谢物删除。本附件的树定义了本次基准的待比较前体，不要求恢复原实验中未列入树的所有试剂。若另做忽略部分物质的宽松匹配，应显式命名、对两来源和参考使用同一规则，并与严格主指标分开报告。

### 参考字段与候选字段隔离

完整参考树、metadata.smiles、metadata.rsmi、metadata.ID、reaction_hash 和后续中间体不传入模型、数据库查询、融合或评分。候选真实携带的酶编号和其他证据可以参与项目原有评分；参考结构不参与调分。

本附件未提供酶编号字段，不能据此判无效，也不能默认这些专利反应全部是酶促反应。正式测试按所选 n1、n5 样本运行，不根据数据库是否命中或模型是否熟悉某类反应事后删样本。报告说明所用本地模型后端与数据库范围。

参考分子无法解析属于 invalid_reference；预测分子无法解析属于 invalid_candidate。前者在正式推理前识别，后者保留候选记录。不得用模型或数据库本次生成的路线反过来修补参考答案。

## 8 统计指标与计算示例

### Top 1 至 Top 3 的累计规则

| 正确候选的合并排名 | Top-1 | Top-2 | Top-3 | 继续扩展 |
| --- | --- | --- | --- | --- |
| 第 1 名 | 1 | 1 | 1 | 是 |
| 第 2 名 | 0 | 1 | 1 | 是 |
| 第 3 名 | 0 | 0 | 1 | 是 |
| 第 4 名及以后 | 0 | 0 | 0 | 是 |
| 合并池不存在 | 0 | 0 | 0 | 否 |

每个已尝试步骤的 topj_hit = 1，当且仅当正确候选存在且 hybrid_rank≤j；否则为 0，j 仅取 1、2、3。未访问步骤的三个标记均为 null。

Top-j 准确率＝符合 hybrid_rank≤j 的已尝试步骤数／已尝试步骤数。首次 miss 的步骤计入分母，后续未访问步骤不计入。此指标是在参考引导下实际访问步骤上的条件准确率，不能解释为所有参考步骤的独立单步准确率。

### 路线覆盖和引导完成

每条路线返回 found_steps、total_steps、attempted_steps、not_evaluated_steps、coverage_ratio、status，另保存可读的 coverage_text，例如 2/3。

coverage_ratio = found_steps / total_steps。设按固定遍历顺序的第 t 步首次 miss，则 found_steps=t−1、attempted_steps=t、not_evaluated_steps=L−t。完整命中时 found_steps=attempted_steps=L，覆盖比例为 1。

每组分别汇总：路线覆盖比例的算术平均值；总命中步数／总参考步数；complete 路线数／正常完成评估路线数。最后一个分母只包含 complete 与 miss。Top-j 汇总先累加命中次数和尝试次数再相除，不能简单平均每条路线的百分比。所有比例保存分子、分母及数值，零分母为 null。

### 三步路线示例

A←B*←C*←D：第一步仅数据库命中，合并排名第 2；第二步仅模型命中，合并排名第 5；第三步两来源均未命中。前两步都继续，第三步停止。

结果：found_steps=2，total_steps=3，attempted_steps=3，coverage_ratio=2/3。Top-1=0/3，Top-2=1/3，Top-3=1/3。数据库命中 1 步、模型命中 1 步、协同命中 2 步。

若第二步即两来源未命中，则返回 1/3，attempted_steps=2；第三步不发起工具调用，Top-2 与 Top-3 为 1/2。覆盖比例与排序准确率的分母不同，不能混淆。

## 9 来源归因与运行异常

### 区分协同结果和来源贡献

在同一批正常评估的已尝试步骤上，统计 database_hit、model_hit、both_hit、database_only、model_only、neither_hit。两来源均命中只增加 1 个协同命中步骤。

model_hit 只表示模型原始候选池实际包含参考组合，不能因为数据库检索成功就标为模型正确。来源命中取自冻结的原始来源记录，而不是仅依据融合后的 BOTH 标签；融合必须满足 hybrid_hit = database_hit OR model_hit。

这些来源统计属于同一次协同引导过程的归因，不等于单独使用数据库或单独使用模型的完整消融实验。若以后开展独立消融，应分别执行各自引导流程，本次不强制增加。

### 明确状态与统计分母

complete：全部参考步骤命中。miss：两个来源均正常执行，但本步均不含正确候选；正常返回空列表也属于 miss。

invalid_reference：数据结构或参考分子无法合法解析。error：模型、数据库或评分器异常。budget_exceeded：超时、调用次数或其他预算不足造成中断。not_evaluated 是未访问步骤的状态，不是路线失败原因。

任一来源发生运行异常时，不能通过另一来源正常返回就把该步骤按完整协同测试计分。停止当前路线，记录错误源与发生位置；保留之前的成功评估步骤，异常步骤不增加 attempted_steps，另记录 started_steps 或调用日志以反映已发起的工作。

主性能汇总只纳入最终状态为 complete 或 miss 的路线。invalid_reference、error、budget_exceeded 分别报告数量及原因，它们的中断前进度保留在逐路线记录，但不混入主 Top-j、覆盖率或完成率分子分母。

报告 total_selected_routes、valid_reference_routes、scored_routes、invalid_reference_routes、error_routes、budget_exceeded_routes，保证选择的每条路线都有去向。scored_routes = complete_routes + miss_routes。分组处理完全部所选记录后，报告主指标实际覆盖了多少条路线，不能只展示成功运行的部分。

### 可复现运行

保存数据、代码、数据库、模型权重及配置标识，随机种子、规范化规则、候选预算、真实解码限制、评分字段与方向、融合规则、遍历顺序和底物策略。支持固定样本区间，先校验数据再执行推理。

缓存命中可以复用既有工具结果，但每个被尝试步骤仍记录双来源调用请求；区分请求数与实际模型推理或数据库查询数。缓存键包含所有影响候选的条件，尤其当前产物、路线底物、后端、权重和生成配置。原始候选与评分缓存分开，不能跨不同状态错误复用分数。

续跑时检查数据及配置一致，按 dataset_split、route_id 和节点身份识别结果，避免重复计数。缺少模型或数据库等初始化条件时清晰报错；不要静默切换数据源或后端。

## 10 输出文件与运行入口

### 结果文件

输出根目录下分别建立 n1、n5 子目录，保存各自路线、步骤、候选和汇总结果。记录之间以 dataset_split、route_id、step_id 关联，并可追溯 source_file、source_route_index 与 JSON 节点路径。

routes.csv：每条所选路线一行。包含目标、路线底物、状态、found_steps、total_steps、attempted_steps、not_evaluated_steps、coverage_ratio、coverage_text、三个 Top-j 命中次数、停止步骤与原因、耗时。

steps.jsonl：每个参考反应一条记录，包括 product、reference_precursors、节点连接、状态、两来源候选数量、database_hit、model_hit、hybrid_hit、hybrid_rank、三个 Top-j 标记、匹配候选编号、耗时与异常信息。未访问步骤保留记录，预测与评分字段为 null。

candidates.jsonl：保存模型原始返回、数据库原始返回和合并排序三个阶段，含原始与规范化前体、重复次数、来源和反应编号、模型分数、step_score、step_cost、排名、融合映射、无效原因及 would_be_filtered。不能只保存前三名；可使用压缩 JSONL 控制体积。

summary.json：每组的路线去向、参考步数、尝试数、命中数、三个 Top-j、两种覆盖率、引导完成率和来源命中统计。每个比例明确分子、分母及排除项；可另建总报告，保留两组单独结果。

tool_calls.jsonl：记录每次调用请求的路线、步骤、来源、当前产物、参数摘要、返回数量、耗时、缓存和错误。明确 requests、actual_executions 及 llm_api_calls=0。

run_config.json 与 validation.json：分别记录运行配置及文件摘要、数据解析结果和校验错误。校验模式无需加载神经模型或调用候选工具。参考 metadata 可保存到校验或步骤记录中，但不得出现在候选工具输入日志中。

建议新增 chemcrow-public/scripts/evaluate_reference_guided_tools.py，并提供 --dataset-root、--split（n1/n5/all）、--n-model、--n-db、--database-path、--model-config 或等效模型参数、--output-dir、--seed、--start-index、--limit、--validate-only、--resume。下列为待实现接口的命令示例，交付时须按实际实现验证。

python chemcrow-public/scripts/evaluate_reference_guided_tools.py --dataset-root /root/autodl-tmp/my_model/dataset/PaRoutes --split all --validate-only --output-dir results/paroutes_guided_check

少量真实路线测试：
python chemcrow-public/scripts/evaluate_reference_guided_tools.py --dataset-root /root/autodl-tmp/my_model/dataset/PaRoutes --split all --n-model 10 --n-db 20 --start-index 0 --limit 2 --output-dir results/paroutes_guided_smoke

--start-index 从 0 开始，--limit 在 split=all 时分别应用于 n1、n5。10 和 20 仅为候选预算示例，不是固定最优值。正式全量命令移除样本限制，并使用已确认的模型、数据库与候选配置。

## 11 实施顺序与验收要求

### 实施顺序

先检查本地接口并实现 PaRoutes 适配器；再抽取完整双来源候选获取、融合与评分接口；随后实现引导控制器、统计与输出。共享逻辑复用项目代码，测试模式的改动不应改变现有 Agent 和自主搜索的默认行为。

先跑全部数据的结构校验，再用模拟工具验证命中和停止逻辑，最后用 n1、n5 各少量真实路线验证工具接入。模拟工具用于验收流程，不能作为正式模型性能结果。模型或数据库不可用时，完成可做的开发和模拟验收，并明确剩余阻碍。

### 必须通过的验收

1. 实际附件的 n1、n5 均解析为 10,000 条路线；反应总数分别为 31,785、38,483。顶层反应 smiles 为空不应导致无效记录；适配器自动生成 reference_steps。

2. n1 的 source_route_index=0 有 8 个反应、最长分支 8 步、7 个叶节点。n5 的 source_route_index=0 有 10 个反应、最长分支 9 步、7 个叶节点。总步数必须取 10，不能把后者算为 9。

3. n1 的 source_route_index=236 中，分子节点路径 /children/0/children/1 的后续反应有三个前体，其中两个为 O；n5 的 source_route_index=360 的根反应同样有两个 O。前体顺序可变，但删掉一个 O 后不得命中。默认不能忽略水。

4. 数据库独自命中、模型独自命中、两者均命中都继续；两个来源均未命中即停止。正确候选排第 1、2、3、5 名时，累计 Top-j 标记正确，四种情况均继续扩展。

5. 首步 miss 返回 0/L，attempted_steps=1；中途 miss 后没有任何后续候选调用；全命中返回 L/L。多前体匹配失败、任一 AND 分支失败，也立即停止整条路线。

6. 完整组合相同可以合并来源证据；主前体相同而其他前体不同必须分别保留。来源中存在的正确组合不能在融合、currency 去重或普通搜索剪枝中消失。

7. 规范化后的等价 SMILES 可匹配；映射编号不影响匹配；默认保留立体、电荷和同位素差异。覆盖空列表、返回不足预算、重复候选、并列分数、无效分子、工具异常、超时及续跑重复计数。

8. 对照第 8 节的三步示例检查全部分子、分母，满足 Top-1≤Top-2≤Top-3。两组分别统计，跨组重复目标不静默删除；库存命中与数据库锚定不能跳过参考步骤。

9. 不配置任何语言模型 API 密钥也能运行；验收中阻断远程语言模型请求并确认调用次数为零。工具输入不含参考下一步、参考反应编号或未来中间体。
